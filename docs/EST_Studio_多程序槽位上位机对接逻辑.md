# EST Studio 多程序槽位上位机对接逻辑

## 1. 文档信息

| 项目 | 内容 |
| --- | --- |
| 文档版本 | 0.3 |
| 更新日期 | 2026-08-29 |
| 当前状态 | 第一版闭环已在 M1.10A 真机通过两轮验收 |
| 适用范围 | EST Studio 多程序槽位的下载、运行与终止功能 |

## 2. 目标

EST 设备提供 `0–7` 共八个程序槽位。EST Studio 需要让用户将当前积木工作区生成的 Python 程序写入指定槽位，并完成以下三项操作：

1. 下载当前程序到选中槽位。
2. 下载当前程序到选中槽位，成功后立即运行。
3. 终止当前正在运行的用户程序。

本文档定义上位机业务逻辑，并记录 M1.09A 已确认的 HID 命令、报文和执行顺序。

## 3. 已确认的用户操作规则

### 3.1 槽位选择

- 用户可以选择槽位 `0–7`。
- 槽位选择器只显示当前选中的槽位。
- 界面不标记正在运行的槽位。
- 第一阶段不显示槽位为空、已占用或程序名称等状态。
- 选中的槽位同时作为“下载”和“运行”的目标槽位。

### 3.2 下载按钮

点击“下载”后，上位机将当前积木工作区生成的程序直接写入选中槽位。

- 槽位中已有程序时直接覆盖，不弹出覆盖确认。
- 下载成功后不自动运行。
- 下载失败时保留错误信息并恢复界面操作。

### 3.3 运行按钮

点击“运行”不是运行槽位中的旧程序，而是执行固定流程：

```text
生成当前程序
→ 校验程序
→ 下载并覆盖选中槽位
→ 等待下载成功响应
→ 通知下位机运行选中槽位
```

- 每次点击“运行”都会使用当前用户界面中的最新程序。
- 下载没有成功时，禁止发送运行指令。
- 运行其他程序时是否需要先终止旧程序，由下位机协议或 `EST Device Service` 内部处理，不增加用户操作步骤。

### 3.4 停止按钮

红色方块按钮定义为“停止”，不定义为“暂停”。

点击后，上位机发送“终止当前用户程序”指令。下位机负责结束用户程序，并自行完成电机安全停止。上位机不直接发送电机停止指令。

### 3.5 本地工程与设备槽位

- `.ests` 文件保存的是电脑上的用户工程。
- 保存 `.ests` 文件不会自动写入 EST 设备。
- 只有点击“下载”或“运行”才会向设备传输程序。
- 当前槽位选择属于部署设置，不改变积木工程内容。

## 4. 上位机模块边界

```text
界面层
  │  下载 / 运行 / 停止 / 槽位选择
  ▼
程序操作控制器
  │  流程编排、状态控制、错误反馈
  ├──────────────► Python 程序生成器
  │                 积木转代码、语法检查、生成程序数据
  ▼
EST Device Service
  │  下载会话、分包、确认、超时和命令调用
  ▼
HID Transport
  │  HID 报文收发
  ▼
EST 下位机
```

界面层不得直接拼装或发送 HID 报文。下位机协议变化应集中在 `EST Device Service` 和 HID 协议层处理。

## 5. 上位机业务接口

程序操作控制器建议提供以下接口：

```js
downloadCurrentProgram(slot)
downloadAndRunCurrentProgram(slot)
terminateCurrentProgram()
```

`EST Device Service` 建议提供以下接口：

```js
downloadProgram({slot, source, programName})
runProgram({slot, source, programName, timeoutMs})
stopCurrentProgram()
```

`downloadProgram` 执行 RAM 上传和槽位保存；`runProgram` 在此基础上继续加载槽位并启动；`stopCurrentProgram` 只终止用户程序，电机安全停止由下位机完成。

## 6. 程序数据对象

建议在上位机内部统一使用以下结构：

```js
{
    slot: 0,
    source: 'import est\n...',
    programName: 'Program 0',
    timeoutMs: 10000
}
```

| 字段 | 说明 |
| --- | --- |
| `slot` | 目标槽位，范围为 `0–7` |
| `source` | 当前代码区中的 Python 源码，由主进程编码为 UTF-8 |
| `programName` | 写入持久化槽位的名称，当前默认 `Program N` |
| `timeoutMs` | 用户程序硬执行上限，范围 `100–10000 ms` |

主进程计算 UTF-8 字节数和 IEEE CRC32；源码最大为 8192 字节且不得包含 NUL。

## 7. 操作状态机

上位机内部建议使用以下状态：

| 状态 | 含义 |
| --- | --- |
| `IDLE` | 等待用户操作 |
| `GENERATING` | 正在把积木转换为 Python |
| `VALIDATING` | 正在检查程序和槽位参数 |
| `DOWNLOADING` | 正在建立下载会话并传输程序 |
| `STARTING` | 下载成功，正在请求运行程序 |
| `STOPPING` | 正在请求终止用户程序 |
| `SUCCESS` | 操作成功，短暂提示后返回 `IDLE` |
| `ERROR` | 操作失败，显示错误后返回 `IDLE` |

同一时间只允许执行一个下载或运行流程，避免多个 HID 下载会话相互干扰。

## 8. 详细流程

### 8.1 下载当前程序

1. 检查 EST 是否已连接。
2. 检查槽位是否在 `0–7` 范围内。
3. 锁定下载和运行按钮，状态进入 `GENERATING`。
4. 将当前积木工作区生成 Python 程序。
5. 执行 Python 语法检查。
6. 将程序编码为下位机要求的字节数据。
7. 计算程序长度和完整校验值。
8. 调用 `downloadProgram(slot, artifact, onProgress)`。
9. 等待下位机完成校验和槽位写入。
10. 收到成功响应后提示“已下载到槽位 N”。
11. 恢复按钮并返回 `IDLE`。

任一步骤失败都立即结束流程，且不会发送运行指令。

### 8.2 下载并运行当前程序

1. 完整执行“下载当前程序”流程。
2. 只有收到下位机明确的下载成功响应后，状态才进入 `STARTING`。
3. 调用 `runProgram(slot)`。
4. 收到运行成功响应后提示“程序已启动”。
5. 恢复按钮并返回 `IDLE`。

运行失败不会删除已经成功下载到槽位中的程序。

### 8.3 终止当前用户程序

1. 检查 EST 是否已连接。
2. 状态进入 `STOPPING`。
3. 调用 `terminateProgram()`。
4. 等待下位机返回终止结果。
5. 成功时提示“程序已终止”。
6. 失败时显示明确错误，不假定程序已经停止。
7. 返回 `IDLE`。

停止属于安全操作。最终协议需要明确停止指令在程序下载期间的优先级，以及是否需要先取消下载会话。

## 9. M1.09A 正式命令

| 命令 | Action | 载荷 | 作用 |
| --- | ---: | --- | --- |
| `0x24` | `0x00` | action | 查询 RAM Python 状态 |
| `0x24` | `0x01` | action + length(u16 LE) + crc32(u32 LE) | 开始 RAM 上传 |
| `0x24` | `0x02` | action + offset(u16 LE) + 最多 1000 字节 | 上传源码分包 |
| `0x24` | `0x03` | action + timeoutMs(u32 LE) | 启动 RAM 程序 |
| `0x24` | `0x04` | action | 终止当前程序 |
| `0x24` | `0x05` | action | 清空 RAM 程序 |
| `0x25` | `0x00` | action + 可选槽位 | 查询持久化槽位 |
| `0x25` | `0x01` | action + 槽位 + 名称长度 + UTF-8 名称 | 把 RAM 程序保存到槽位 |
| `0x25` | `0x02` | action + 可选槽位 | 把槽位程序加载到 RAM |
| `0x25` | `0x03` | action + 可选槽位 | 清除槽位 |

槽位范围为 `0–7`，名称最长 31 个 UTF-8 字节。所有多字节整数均为小端；沿用 EST 帧头、方向、长度、逐字节和校验及帧尾格式。

## 10. 下载可靠性要求

- M1.09A 持久化层使用双 bank 提交；完整写入和校验成功后才切换有效记录。
- 下载失败、中断或校验失败时，应保留槽位中的旧程序。
- RAM 分包以源码偏移量定位；每包等待 `0x24` 状态响应后再发送下一包。
- 第一版不自动重试写操作，超时后直接报告失败，避免不确定状态下重复提交。
- `STOP` 后轮询 `0x24 STATUS`，直到下位机清除 timeout-armed 标志并完成退出清理。
- 连接断开后，上位机清理本地下载会话；重新连接时不自动续传。

## 11. 错误处理

| 错误类型 | 上位机处理 |
| --- | --- |
| EST 未连接 | 阻止操作并提示连接设备 |
| 槽位超出范围 | 阻止发送 |
| Python 生成失败 | 显示代码生成错误 |
| Python 语法错误 | 不开始下载 |
| 下位机拒绝下载 | 显示下位机返回的原因 |
| 分包超时 | 按协议重试，超过限制后终止下载 |
| 校验失败 | 不提交程序、不发送运行指令 |
| 存储空间不足 | 显示空间不足 |
| 运行失败 | 保留已下载程序，显示启动失败 |
| 终止失败 | 显示终止失败，不假定程序已停止 |
| 连接中断 | 结束当前流程并清理通信会话 |
| 协议版本不兼容 | 禁止下载并提示升级软件或固件 |

## 12. 第一阶段范围

第一阶段只实现：

- 选择槽位 `0–7`。
- 下载当前程序。
- 下载当前程序并运行。
- 终止当前用户程序。
- 操作进度和成功、失败反馈。

第一阶段暂不实现：

- 正在运行槽位标记。
- 槽位占用状态显示。
- 从下位机读取或反编译槽位程序。
- 槽位重命名。
- 同时运行多个槽位。
- 暂停和恢复程序。

## 13. 联调验收要求

1. 当前程序能够分别下载到槽位 `0–7`。
2. 下载到已有程序的槽位时能够正确覆盖。
3. 点击“下载”后程序不会自动运行。
4. 点击“运行”时必须先完成下载，再启动对应槽位。
5. 下载失败时不会发送运行指令。
6. 运行失败时已下载程序仍然保留。
7. 下载中断不会破坏槽位中的旧程序。
8. 断电重启后槽位程序仍然存在。
9. “停止”能够终止当前用户程序。
10. 用户程序终止后，下位机能够自行安全停止电机。
11. 非法槽位、校验失败、空间不足和连接中断均能返回明确错误。

## 14. 第一版实现说明

- M1.09A 运行用户程序时拒绝新的 BEGIN，因此 Device Service 会在上传前查询状态；存在 queued/running 程序时先发送 STOP 并等待清理完成。
- 运行操作收到 queued/running 确认后即返回界面，不等待用户程序自然结束，从而保证停止 IPC 可以继续进入命令队列。
- 持久化保存可能需要擦写 Flash，`0x25` 单次请求超时为 15 秒；普通 `0x24` 请求超时为 2 秒。
- 后续联调仍需验证下载期间断开、Flash 写入失败、8 个槽位断电保持及 10 秒硬超时等真实设备边界场景。

## 15. M1.10A 第一版验收基线

### 15.1 基线范围

2026-08-29 使用 M1.10A 真机完成 EST Studio Python 程序闭环验收。验收覆盖：

1. 将当前 Python 源码通过 `0x24` 上传到 RAM。
2. 通过 `0x25` 将 RAM 程序保存到选定槽位。
3. “运行”操作重新保存当前程序、加载选定槽位并启动。
4. 用户程序运行期间通过 `0x24 STOP` 终止程序。
5. 用户程序运行期间，`0x19` 状态轮询超时不关闭 HID transport，停止按钮仍能使用原连接发送 `0x24 STOP`；程序停止后恢复正常状态轮询。

### 15.4 验收结论

M1.10A 与当前 EST Studio 已完成第一版 Python 程序下载、持久化槽位保存、加载运行和停止闭环。纯 `import est` 与积木生成的 `import est_runtime as rt` 两条程序路径均已通过真机验证，主进程未记录 EST 操作失败或设备断开错误。

本次验收不代表所有边界场景已经完成。槽位 `0–5`、下载中断、Flash 写入失败、八槽位断电保持、程序自然结束、异常退出和 10 秒硬超时仍按第 13、14 节继续列为后续验收项；在开始这些工作前不扩展新的上位机功能。
