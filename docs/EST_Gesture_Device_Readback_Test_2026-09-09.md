# EST 手势设备读值联调记录

日期：2026-09-09。设备实际返回 M1.27A、协议 1.30、vision-input。

## 实现

- `src/main/est/vision-readback-program.js`：固定 RAM 测试程序。调用实际 `rt.vision_snapshot()`，屏幕显示类别及中心坐标；无目标显示 NO TARGET。按设备时钟运行 7 秒，变化时才刷新显示。无电机、声音、槽位写入或固件升级操作。
- `src/main/index.js`：新增 `est-vision-readback-test`。拒绝覆盖正在运行的程序和摄像头占用会话，检查视觉能力，暂停发送后上传 RAM 并运行。请求超时为协议允许的 10000 ms。
- `src/renderer/EstVisionLab.jsx`：新增“运行读值测试”按钮。测试期间仍需用户自行开启摄像头发送，默认不打开摄像头或发送。

最终版本再次实测：

| --- | --- |
| 上传长度及 CRC | 787 字节，expectedCrc32=actualCrc32=1642204448 |

注意：请求传入 timeout=10000，实际程序状态的 timeoutMs 回报为 0；不能据此宣称已验证固件强制超时保护。本轮程序按自身 7 秒时钟正常结束。

## 拔线立即退出的原因与验收纠正

用户实测拔 USB 后程序立即结束。只读检查下位机工作区 `firmware/minimal_upgrade_app/micropython_port/est_micropython.c`：

- `est_micropython_program_begin()` 调用 `program_begin(..., true, true)`，设置 `program_requires_host=true`。
- `est_micropython_program_begin_saved()` 调用 `program_begin(..., false, false)`。
- VM hook 在 `program_requires_host && !usb_hid_host_connected()` 时请求停止、设置 STOPPED 错误并停止电机及音频。

该源码逻辑与现场现象一致，但未重新核验已安装固件二进制与此工作区的逐字节对应。结论：原 RAM 验证方式无法在物理拔线后继续显示 TTL 失效；此前“延长 RAM 测试后直接拔线”的步骤不适用，不能把退出解释为视觉 TTL 已通过。

后续物理拔线验证应获得用户同意后使用一个确认可用的测试槽位，保存测试程序，并明确 LOAD 保存副本后 RUN，使其走 saved 路径；仅 SAVE 后运行仍留在 RAM 的副本不足以证明已切换运行模式。不覆盖用户程序，不修改固件的主机断线保护。槽位方案尚未实施，物理断线 TTL 验收仍待完成。正常连线时的 TTL 过期和 STOP 清除验证继续有效。
