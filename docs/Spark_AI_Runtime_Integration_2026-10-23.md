## 2.8.51 自动发现与重连

- 选择 Spark AI 后，在主进程自动发现 USB 设备，不必打开连接面板。断开时每 2 秒枚举一次，连接正常时不持续枚举；多个界面的刷新共用一个枚举请求。
- 首次仅将 USB VID/PID `0483:5740` 作为候选。这也是通用 STM32 CDC 标识，不足以确认型号，所以先被动等待合法 Spark 监控，收到后才发送 BA 开启监控。其他串口和蓝牙 COM 口不会自动尝试打开，仍保留手动连接。
- 多个候选不逐个试连，由用户选择。成功连接后在当前软件会话内记住 USB 序列号（无序列号时使用 USB PNP 标识）；普通断线只重连同一标识，允许 COM 号变化，不替换成另一台设备。缺少可用标识时改为手动选择。重启软件后重新做被动验证。
- 失败按 10、20、30 秒退避，最高间隔 30 秒；确认设备离开枚举列表后清除该设备退避。首次设备若已关闭主动监控，需要手动连接，不向尚未验证的设备盲发指令。
- 连接面板增加“自动连接”复选框及五种语言状态。用户主动断开会关闭自动连接，可手动重新启用；关闭面板不等于断开设备。
- 自动连接只建立通信并开启监控，不发送停止、下载或运行命令，不恢复上一次程序操作。编译、下载、停止等事务期间不扫描或尝试连接。
- 下载中取消、应答错误或断线会锁定自动重连；切换硬件或开关自动连接不能解除锁定。用户按提示断电重启后手动连接成功才解除，随后仍需重新完整下载。软件不能仅凭相同版本号证明设备已断电。
- 切换到 EST / New AI 或退出软件时停止扫描；异步枚举晚到也不能连接旧硬件。状态变化按原有节奏合并，并使用发现状态修订号避免每条监控都刷新已关闭的连接面板。

新增模拟回归覆盖：USB/蓝牙过滤、陌生 STM32 被动验证、多设备选择、同机换 COM、不同设备拒绝替换、失败退避、主动断开暂停、手动恢复、扫描合并、硬件切换迟到结果及下载恢复锁定。

## 使用方式

1. 进入工作区，在顶部硬件选择器选择 Spark AI。
2. 单台候选设备将自动验证并连接。也可点击旁边的连接状态，选择 Spark AI 的 USB 串口后手动连接；“自动连接”控制后台发现和重连，单独刷新列表不会直接打开串口。
3. 收到合法监控后显示固件版本、电量、A–D 传感器、存储和设备输出。当前只允许向已按源码核对的版本 `110` 下载；其他版本仍可查看监控和请求停止，但不自动升级。
4. 在右下角选择槽位 `0–9`。下载按钮只保存；运行按钮重新编译并下载，以 BC 末帧请求启动所选槽位。更换槽位本身不向设备发命令。
5. 停止按钮发送 B9，等待新的 `WillAiState=stop`，再等待 2 秒收尾。该状态仍不等于固件确认了全部资源清理。

断开连接不保证板端程序结束。运行中主动断开会先要求用户确认；切换硬件则沿用停止确认，并等待当前硬件的停止流程后再断开。下载、编译、连接或监控切换进行中禁止切换硬件。

下载中取消、应答异常或拔线时不重发、不续传，关闭串口并提示将主机断电重启，然后重新连接并完整下载。协议没有设备唯一 ID 或启动计数，软件不能自动证明用户确实重启过设备。

## Python 到字节码

使用原 Spark AI 1.1.9 的 PikaPython 1.13.4 native 编译器，不调用系统 Python，也不执行用户源码。编译在独立子进程中进行；每次创建独立临时目录，传入 ASCII 相对文件名 `program.py` 和 `program.py.o`，支持中文安装和临时路径。取消或 20 秒超时会终止子进程；编译完成后删除本次任务目录。

编译器资源位于 `resources/spark-ai/`，打包时复制到 `resources/spark-ai`，不依赖本机 E 盘。资源包含 worker、编译器清单、PikaPython MIT 许可和 Windows x64 `.node`：

```text
471040 bytes
SHA256 902f43061019656d118f27e2856ec6a04116bdf161a62d5d84d587b2cc85e2f5
```

发送前检查 native 返回值、本次新产物、Pika 魔数、文件内部长度和小于 32768 字节的限制。语法错误、缺少产物或异常退出不会进入文件发送流程。编译器不验证板端 API 是否存在；列表接口、音符名称和灰度比较等固件差异仍需按积木接入说明实机确认。

`scripts/import-spark-runtime.js` 仅用于维护时从原安装资源校验并导入编译器，同时导入两份原始编译样本作为仓库内测试预期。正常启动、编译及测试不需要提取包目录。其他平台的编译器尚未提供，运行和下载按钮不可用。

## 传输与状态

```text
5A 97 98 LEN CMD PAYLOAD SUM8 A5

DA(ASCII N.o) -> FD/01
AA(中间片段) -> FD/01，按需重复
BB(最后片段) -> FD/01，只保存
BC(最后片段) -> FD/01，保存并请求启动
```

USB 每片最多 248 字节，末帧携带最后一段内容，不追加空结束帧。严格检查长度、累加校验、A5 帧尾和 `FD/01`；FATFS 错误、F3、F4、FF 不当作成功。每片等待完整应答，默认 5 秒超时，无自动重试。编译失败不打断板端现有程序；编译成功且准备下载时才按需停止现有程序。

接收解析器处理任意串口拆包、粘包，以及混合的二进制应答、JSON+CRLF 和脚本日志。限制文本和接收缓冲大小；设备日志有界保存。主进程状态通知最多约每 100ms 合并一次，界面只更新连接/操作控件和已打开的状态面板，不轮询 Blockly 或触发工具箱重建。最后一个 Spark 控件卸载时移除渲染进程订阅。

下载期间固件会暂停监控，因此不会因这段正常静默判定断线。非下载状态下监控超过 5 秒未更新会标记过期，阻止继续下载；停止按钮仍可使用。监控开关发送 BA/BE，下一次程序操作会按需重新开启监控并等待新数据。

界面分开表达三个结果：

| 结果 | 可证明的事情 |
| --- | --- |
| 编译完成 | 本次产物有效，非旧文件 |
| 已下载到槽位 | 最后一个文件应答已通过校验 |
| 已观察到运行标志 | BC 之后捕获过 `WillAiState=run`，包含早于最后 ACK 的情况 |

固件没有独立的执行成功/执行错误 ACK。短程序可能在监控间隔内结束；等待 3.5 秒仍未捕获 run 时显示“已下载并请求启动，未捕获运行状态”，不自动重跑，也不误报执行成功。USB 脚本错误可在设备输出区查看。

## 2.8.52 蓝牙接入

入口：选择 Spark AI 后，点顶部连接状态，切换“蓝牙”，搜索并明确选择设备。搜索可取消，30 秒自动结束；关面板取消尚未完成的搜索，已建立的连接继续提供监控。断开后需手动重新搜索连接，不自动运行程序。切回 USB 后沿用原有 USB 自动连接偏好。

- 使用 Electron 内置 Web Bluetooth，不增加 native 蓝牙依赖、不修改 node_modules。主进程仍负责协议、编译、ACK、下载互斥和运行状态，渲染进程只管理 GATT 对象。选择流程遵循 [Electron 设备访问文档](https://www.electronjs.org/docs/latest/tutorial/devices) 的 `select-bluetooth-device` 模式，始终 preventDefault，不默认连接第一个候选。
- 扫描按 FFF0 服务或 `Spark` / `EST_BLUE` 名称前缀筛选；连接后必须找到 FFF0 服务、FFF1 可写/可通知特征、订阅成功，并收到结构合法的 Spark 监控。Electron chooser 地址与 Chromium 不透明设备 ID 分开绑定，避免误把两者视为同一 ID。
- USB 与 BLE 共用一个设备服务，但通道互斥。程序运行中或下载中不能切换；选择 BLE 时暂停 USB 自动发现。内部适配器标识仍保留 `spark-usb`，避免无关项目格式和硬件切换重构。

- 下载、下载后运行、停止分别复用 DA/AA/BB、DA/AA/BC、B9 流程，不使用 B6 冒充“运行指定槽位”。断线/取消造成文件事务不确定时，要求设备断电重启后完整下载。

## 2.8.54 USB 固件更新

本节取代 2.8.53 的禁止刷写状态。现已接通 Spark AI USB 主控更新，内置资源仍是原软件版本 110 的五文件原包。未重新编译或修改 APP/Bootloader，不修改已有 EST HID 更新路径。

流程与实现：

1. 固件服务先占用 Spark 的更新锁，阻止程序下载/运行/停止、切换通信方式和切换硬件。自动发现及监控超时检查暂停，前端和主进程均检查条件；仅允许主窗口的 Spark IPC 调用。
2. 五个文件在发送 6F 前全部读入内存并按固定 SHA-256 校验。设备身份使用 USB VID/PID 和芯片序列号匹配；COM 号变化不会改连其他设备。普通升级只接受当前已确认的 APP 版本 110。
3. 发送 `6F("RESET_FWLIB")`，释放运行态串口，沿用原软件的 5 秒等待后重新连接同一设备。恢复模式不发送 6F，而是对用户选择的 USB 升级端口直接连接。
4. 依次传输 `app.bin`、`calibrate.o`、`remote.o`、`version.txt`、`updata.txt`。前三个和标志使用 DA 文件名，版本使用 DD；数据片最大 248 字节，中间 AA，末片 BB，不发送 BC。把 `OK` 标志放在最后，避免资源尚未齐备时留下完成标志。该顺序已通过这台设备的实机更新。
5. 每帧必须收到完整且校验通过的 FD/01 才发送下一帧。错误应答、坏 ACK、断线、800ms 应答/写入超时或超过 800ms 的帧间空闲立即结束，不重发、不续传。所有文件已在内存中，发送循环内不读磁盘，也没有暂停按钮。
6. 文件确认完成后显示等待设备安装并启动。仅被动等待 APP 监控，不向仍可能处于 Boot 的通道插入 BA 或其他控制。需要时按相同设备身份重新打开串口，最多等待 45 秒。收到有效 APP 监控且版本为 110 后，恢复普通设备连接与 BA 监控，并再次核对版本。
7. 完成结果分别记录 `transferComplete`、`reconnected`、`versionMatched`；`imageVerified=false`，因为原协议没有整 Flash 回读哈希。最后文件 ACK 不单独触发成功提示。失败会保留恢复状态，暂停自动连接并显示具体原因；资源预检失败不向设备写命令，也不会清除已有恢复状态。

更新进度沿用主进程 100ms 合并推送。更新期间关闭面板不停止传输，重新打开会显示正在进行的更新；主窗口关闭和应用退出在实际更新期间被阻止，完成后恢复。界面文案覆盖简中、繁中、英文、葡萄牙文和俄文。

## 2.8.56 下载中断仅提示

- `recoveryRequired` 运行时标记仅用于固件更新；实际更新中的独占、恢复更新要求及资源/状态校验不变。本轮没有重新刷固件或修改下位机。
