## 2. 优先解决的兼容性与可靠性缺口

| 项目 | 当前证据及影响 | 建议下一步 |
| --- | --- | --- |
| 5 个列表 API 不匹配 | 生成器仍使用 `remove_index`、`remove_all`、`dataToindex`、`num`、`list_if_data`；所给 List 声明、绑定和实现未提供这些方法。积木可见、代码可编译，不能据此宣称板端执行成功 | 先做无电机实机用例，再用已确认的 `pop`、继承的长度能力、遍历等实现兼容映射；同时核对积木 1 起始索引与运行时索引语义。不能只替换方法名 |
| 灰度比较语义不一致 | 当前直接生成 `_color.cmp_lux`。所给 C 源码中 `<` 实际为 `lux <= value`，`>` 为 `lux >= value`，`=` 为 `lux != value` | 真机验证边界值，决定在生成器以读数+常规比较实现，还是由固件修复；保留对旧工程行为改变的说明 |
| 监控静默时没有主动恢复 | 当前 watchdog 在约 5 秒无有效监控后标为 `monitor-stale`，阻止下载；串口仍打开时不会触发自动发现。之后若收到有效监控，可自行清除过期错误 | 设计受限的监控恢复流程，区分用户关闭监控、下载暂停、设备忙与真实失联；避免盲目重发或停掉用户程序 |
| 偶发无效 JSON 尚未定位 | 换口后 30 秒原始接收观察：2918 条合法 JSON、1 条多余右花括号的非法 JSON。现有解析器跳过该条并记日志，后续有效数据继续更新 | 保留原始样本，区分发送端拼接、USB 数据链路与接收处理；补异常报文计数/采样回归。不能未经证据认定全是固件问题 |
| 音符菜单覆盖不完整 | 菜单为 `C C# D E# E F F# G G# A B# B`。所给解析器支持升降号和默认第 4 八度，`E#` 等同 `F`，`B#` 跨至下一八度 `C`；不是“E#/B# 无法解析”。但缺少 `D#`、`A#`，且不是完整音域选择器 | 明确产品所需音域、规范音名并保留旧值兼容；实机验证发声与时长，不沿用 EST 的 MP3 音符方案 |

## 5. 已实现但实机覆盖未完成

- 每类积木和真实外设逐项执行：列表、自制积木、矩阵各操作、音符、E–H 电机/配对/巡线、触碰/超声波/红外等。现有颜色端口数据正常不替代其他类型验收。
- 0–9 全部槽位、重复下载、极短程序未捕获 run 的提示、编译错误与运行错误的区分。
- 下载中取消/拔线、ACK 错误、设备重启后完整重下。模拟测试已有，不要再称为代码未实现，也不要称为真机全部通过。
- 同机 COM 号改变、多台同型号候选、完整物理拔插时序/耗时。当前换口实测仍为 COM3，只证明换物理口后连接和监控正常。
- Spark 新增功能在安装版中的资源路径、权限、首次运行、卸载/升级回归；开发版及原生模块测试通过不等同于最新安装包验收。

## 6. 可独立安排的体验补全

- 2.8.55 已持久化连接方式、自动连接偏好与最近验证的 BLE 身份；启动后重新发现、核对服务并验证监控。最近 USB 身份仍为会话内记录，USB 跨重启按既有唯一候选/被动验证规则连接，不与 BLE 的精确身份记忆混淆。
- 手写 Python 与锁定状态目前按硬件在内存中隔离；没有新增“手写 Python 随项目保存”的持久化格式，不能把当前会话的草稿当永久保存。
- 日志已有查看、复制、清空；尚无交互式 REPL、错误行跳转或结构化诊断。普通脚本日志与无效监控目前共用文本日志通道。
- New AI 仍只是可选硬件占位：无积木、编译器或协议。这是另一款设备的接入任务，不混入 Spark 的缺项数量。

## 7. 建议执行顺序

1. 当前推进蓝牙剩余验收，保留每项实测记录；区分自动化、实际 GATT 断线、软件重启和设备断电。
2. 随后核对无电机兼容性问题：列表方法/索引、灰度比较、音符菜单；不因不支持旧工程迁移而忽略当前积木行为。
3. 完善静默监控恢复与异常诊断，补齐外设、故障及安装版回归。
4. 电脑遥控先明确界面与失联释放方案，再实施；视觉输入排后期。
5. 原工程迁移、传感器升级和免下载指定槽位运行不进入开发清单；设备列表等待后续决定。
