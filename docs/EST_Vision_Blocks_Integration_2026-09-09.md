# EST 视觉积木第一阶段接入

日期：2026-09-09。基于用户确认通过的摄像头/HID/槽位拔线测试继续接入积木。
本批只改 Studio，保留工作区已有修改，不修改固件，不提交或推送。

## 积木与数据

传感器分类新增四个积木（原 81 个 EST 积木变为 85 个）：

| ID | 作用 | 生成表达式 |
| --- | --- | --- |
| `vision_valid` | 视觉目标有效？ | `rt.vision_valid()` |
| `vision_gesture` | 当前视觉目标是指定左右手、指定手势？ | `(lambda s: bool(s[0]) and s[1] == CLASS)(rt.vision_snapshot())` |
| `vision_class` | 当前类别编号，无效为 -1 | `(lambda s: s[1] if s[0] else -1)(rt.vision_snapshot())` |
| `vision_position` | X/Y/宽度/高度，0–100，无效为 0 | `(lambda s: s[INDEX] if s[0] else 0)(rt.vision_snapshot())` |

每个表达式只读取一次快照，统一导入 `est_runtime as rt`，不注入命名 helper。
手势下拉为张开手掌、握拳、点赞、食指指向、胜利手势、其他手势。
左手类别 1101–1106，右手 1201–1206；索引 3/4/5/6 为中心 X/Y/宽度/高度。
坐标遵循镜像摄像头预览：X 向右、Y 向下；0 既可能是合法边界，也可能是失效默认值，须配合有效性判断。

当前协议只发送验证页选中的一只手。积木中的左右手是匹配条件，不会切换摄像头的发送目标，
也不代表两个独立传感器。未添加置信度积木：规则手势没有经过标定的置信度，现有发送值为 0。
不把面部动作或人体姿态虚构成固件已确认的类别。

## 固件门禁

使用 `rt.vision_*` 已知读取接口的生成代码要求协议至少 1.30，并具有 bit 30 `vision-input`。
门禁基于 `programCompatible`，不依靠放宽固件兼容开关绕过。
未使用视觉接口的程序不新增要求。普通文字、注释中出现视觉 API 名称不会触发此门禁。
沿用现有电机/显示接口各自的最低固件版本检查，不修改协议消息格式。

## 摄像头生命周期

视觉面板从主页子树移到应用根节点。关闭面板只隐藏面板，切入编辑器不会卸载识别实例。
首次仍须用户打开摄像头；不会随软件启动自动调用摄像头。
编辑器右下方提供摄像头状态/重新打开面板入口，以及停止摄像头按钮。
停止按钮关闭摄像头轨道并停止发送。应用卸载同样清理。

可见面板使用视频帧回调；面板隐藏时使用单个 RAF 链，仅处理变化的视频时间戳。
隐藏面板不绘制关键点；沿用单帧推理、无积压、约 10 Hz 最新视觉帧发送和主进程 300 ms 看门狗。
下载暂停期间保留发送租约，但丢弃视觉帧并清除下载前目标；恢复后只采用新帧。
设备断开仍关闭发送，重新连接后需显式重新启用；不自动重放旧手势。
本批实测覆盖的是软件窗口可见、面板隐藏的编辑状态；窗口最小化/被完全遮挡的持续推理不在本批验收内。
Electron 可能节流此类窗口；若帧停止，看门狗清空目标而不会保留旧手势。

## 下一轮操作

1. 主页 → 其他 → 视觉识别，开启电脑摄像头，选中右手，启用发送到 EST。
2. 关闭视觉面板，进入/返回积木编辑器；确认右下角仍显示摄像头运行中。
3. 创建无电机程序：程序启动 → 重复执行 → 若“视觉右手是点赞”则显示 THUMB，否则若“视觉目标有效”显示 HAND，否则显示 NO TARGET；循环等待 0.1 秒。
4. 下载并运行，观察点赞、张开手掌、手离开画面三个分支。需要左手时同步修改验证页发送手和积木条件。
5. 停止程序后确认目标清空；停止摄像头后确认摄像头指示灯熄灭。
